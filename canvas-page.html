👨‍💻 Code-Together 10: Hash Tables

🎯 Overview

An in-class code-together activity introducing hash tables with separate chaining. Students implement a complete ChainingHashTable class that maps string keys to integer values — using the scenario of a professor’s grade book where student names are keys and grades are values. The activity covers hash function design, collision resolution via linked-list chains, the trailing-pointer removal pattern (from CT8), and dynamic resizing when the load factor exceeds a threshold.

📖 Learning Objectives

By completing this activity, you will be able to:

  • Implement a custom hash function using the multiply-and-add algorithm (×31) with modulo mapping
  • Explain why prime capacity reduces clustering compared to even numbers
  • Implement insert with two cases: update an existing key or prepend a new node
  • Implement search that returns an int* (pointer to value) or nullptr
  • Implement remove using the trailing-pointer pattern from CT8 (head vs. middle/tail cases)
  • Explain load factor as an average across all buckets, and implement resize with rehashing

📝 What You’ll Do

Open each source file and complete the TODO comments. Each TODO tells you what to write, and the DISCUSSION comments explain the “why” behind the code. We’ll work through these together in class.

📚 Teaching Order

Work through the files in order:

1. ChainingHashTable.cpp — Hash table operations (9 TODOs)

Section What You’ll Learn
1. Constructor Allocate a ChainNode** bucket array; understand why prime capacity reduces clustering
2. Destructor Delete every node in every chain, then the array; same temp-pointer pattern from Module 4
3. hash() Multiply-and-add algorithm (×31 per character), then modulo to map into bucket range
4. insert() Two cases: update existing key’s value, or prepend new node at chain head (O(1))
5. search() Hash key, walk chain, return int* (pointer to value) or nullptr
6. remove() Trailing-pointer pattern from CT8; head case vs. middle/tail case vs. not found
7. load_factor() Calculate size_ / capacity_ as double; understand it’s an average, not per-bucket
8. resize() O(n) — allocate new prime-capacity array, rehash every entry, delete old table
9. print() Display each bucket’s chain to verify hash distribution and spot collisions

2. main.cpp — Grade Book Demo (4 TODOs)

Section What You’ll Learn
TODO 1 — Insert students Add 5 students with grades; observe collisions (Alice and Diana share bucket 4)
TODO 2 — Print table View bucket layout and load factor; see collision chain at bucket [4]
TODO 3 — Search Look up existing (Charlie) and missing (Frank) students; int* vs nullptr
TODO 4 — Update & remove Update Bob’s grade via insert (duplicate key), remove Diana from collision chain

🔧 Troubleshooting

CMake does not configure automatically

  1. Make sure you have Desktop development with C++ workload installed in Visual Studio
  2. Go to Project → CMake Settings and ensure the configuration is correct
  3. Try Project → Delete Cache and Reconfigure
  4. Verify that CMakeLists.txt is in the root of your cloned repository

Tests fail to build

  • Google Test is fetched automatically via CMake’s FetchContent — make sure you have an internet connection during the first build
  • Do not modify header files in the include/ folder

Running the Program

  1. In Visual Studio, select ct10-hash-tables.exe as the startup item from the dropdown
  2. Press Ctrl+F5 to run without debugging
  3. You should see output from each section as you complete the TODOs
Tip: Look for the // ! DISCUSSION: comments in each file — these explain the “why” behind each concept. The // ? SEE DIAGRAM: comments point you to visual aids in the images/ folder.
